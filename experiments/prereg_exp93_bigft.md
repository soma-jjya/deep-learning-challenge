## 왜 다시 여는가

1. **추론 축은 수학적으로 닫혔다** (8/23 헤드룸 분해, 교정자 기준 val 483):
   - 오답 103 = 선택 실패 37 (정답이 2등 후보인 건 11개뿐 → 재판별 순이익 상한 ≈ +1) + 능력 한계 41 (32표본 어디에도 정답 없음) + 문제 결함 25 (최종에서 운영진이 회피).
   - n 스케일링 삼중 사망: 시드 42+43+44 합산 n=96 교정자 투표 381 (+1, 노이즈); 실제 LB도 w48=w96=0.78219 < n32w 0.78459.
   - 능력 한계 41문제는 **학습으로만** 닿는다.
2. **유일한 반례 데이터가 오염된 실험이었다**: 외부 데이터 학습의 유일한 전례 exp09b(NuminaMath 30k + 자체 12.9k, QLoRA, lr 1e-4)는 **전체 시퀀스 손실 결함**(2026-08-15 수정) 하에서 돌았다. 문제 본문 암기에 그래디언트 대부분이 소모됐다. 고친 파이프라인 + 대규모 + full FT 조합은 미시도.
3. 3위 참가자 증언: "NuminaMath 전체를 걸러 수십만 개로 full FT, 다수결도 올랐다."
4. 하방이 막혀 있다: 채택 게이트를 못 넘으면 동결 스택(final-rc-20260819)으로 제출. 실패 비용은 시간과 서버 사용뿐.

**성공 확률 사전 추정: 15–30%** (exp09b·teacher·GRPO 등 학습 5전 전패의 사전; 위 1~3이 상향 요인).

## 설계 (실행 전 고정)

### 데이터 (`remote/prep_numina_full.py` → `data/numina_full.jsonl`)
- 출처: AI-MO/NuminaMath-CoT 859,494개 (Apache 2.0, README 데이터 목록 기재).
- 필터 (전부 사전 고정): `boxed` 포함, `extract_answer`로 int64 정수 추출 가능, 풀이 50–3,000자, 문제 ≤1,500자, 문제 텍스트 완전 중복 제거, 검증 500문항 텍스트 제외.
- **자체 데이터 혼합 없음** (순수 외부 — 3위 레시피의 깨끗한 재현).
- 채택 수는 로그로 기록 (예상 20만±, 소스 분포 함께 기록).
- **수정 (8/23 23:55, 학습 4분 시점 중단 후)**: 첫 실행에서 770,662개(90%)가 통과해 표본 검사한 결과 `extract_answer`가 비정수 답(`\frac{\sqrt2}{2}`, `1.92 yuan`)에서도 숫자를 건져 통과시키는 결함 발견. **boxed 내용이 순수 정수(콤마·LaTeX 공백만 허용)인 경우만 채택**하도록 필터 강화 후 데이터 재생성·학습 재시작. 게이트·학습 설정 불변. (전례인 exp09a 30k 데이터도 같은 결함을 공유했음 — 기록용.)

### 학습 (`remote/train_fullft.py`)

- lr **1e-5** cosine, warmup 3%, **1 epoch**, seq 2048, 유효 배치 128 (mb4×accum32), AdamW 8-bit, gradient checkpointing, **assistant-only 손실** (수동 마스킹 — 8/15 수정 계승), seed 42.
- 체크포인트 4개 (25/50/75/100%), 모델만 저장.
