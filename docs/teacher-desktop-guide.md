# Claude Desktop으로 교사 풀이 만들기 — 작업 안내

> 목적: 베이스 모델(Qwen2.5-3B)이 **스스로 풀지 못하는 문제 2,967개**에 대해 고품질 풀이를 확보해
> 학습 데이터로 쓴다. 지금까지 학습 6전이 전부 실패했는데, 6전 모두 데이터가 "모델이 이미 아는 것"
> (RFT 자기생성) 아니면 우리 문제와 무관한 외부 데이터(NuminaMath)였다. 이 데이터는 그 빈칸을 채운다.
>
> 규칙 근거: `prd.md:30` — 학습 데이터 구축 목적의 상용 API/모델 사용은 허용.
> **train 문제만** 사용하므로 `prd.md:31`(테스트 문제 답 생성 금지)에 저촉되지 않는다.
> 추론 단계에서는 어떤 외부 모델도 쓰지 않는다(로컬 vLLM 단독).

---

## 준비된 파일

| 경로 | 내용 |
|---|---|
| `data/desktop/problems_001.md` ~ `problems_149.md` | Desktop에 넣을 문제 묶음 (묶음당 20문제) |
| `data/desktop/INDEX.md` | 진행 체크리스트 |
| `data/desktop/gold.csv` | **정답 — Desktop에 넣지 말 것.** 채점 전용 |

**정답을 일부러 뺐습니다.** 답을 알려주면 모델이 푸는 대신 답에 끼워 맞추는 풀이를 쓰고,
그런 풀이를 학습시키면 정답을 모르는 실제 시험에서 재현되지 않습니다. 나중에 제가 gold와
대조해서 **맞은 풀이만 채택**합니다(틀린 풀이는 버립니다 — 라벨 노이즈 0).

## 1단계 — 프로젝트 만들고 지침 붙여넣기

Claude Desktop에서 새 **프로젝트**를 만들고, 프로젝트 지침(Project instructions)에 아래를 **그대로** 붙여넣으세요.

```
당신은 올림피아드 수준의 수학자입니다. 당신이 쓰는 풀이는 사람이 읽으려는 것이 아니라,
작은 언어 모델(3B)이 학습해서 따라 하기 위한 교재입니다. 그 목적에 맞춰 작성하세요.

풀이 작성 규칙:
- 단계를 건너뛰지 마세요. 3B 모델이 재현할 수 있어야 하므로 산술 한 줄도 생략하지 않습니다.
- 코드 실행·도구·외부 검색을 쓰지 마세요. 순수한 수학적 추론만 사용합니다.
  (학생 모델은 오프라인에서 추론만으로 풀어야 하므로, 도구에 의존한 풀이는 학습 가치가 없습니다)
- 완결성은 유지하되 군더더기는 빼세요. 서론·자기 언급·"이 문제는 흥미롭네요" 같은 문장 금지.
  바로 풀이로 들어갑니다.
- 최종 답은 항상 정수입니다. 정수가 아닌 값이 나오면 계산을 다시 점검하세요.
- 각 풀이의 마지막 줄은 반드시 \boxed{정수} 형태로 끝냅니다.

출력 형식 (반드시 이 형식만 지킬 것 — 자동 파싱됩니다):

## ID: <문제의 ID를 그대로>

<풀이 본문>

\boxed{정수}

주의사항:
- 문제마다 위 블록을 반복합니다. 묶음에 20문제가 있으면 블록도 20개입니다.
- ID는 문제에 적힌 것을 글자 하나 바꾸지 말고 그대로 씁니다.
- 문제 목록을 다시 출력하거나, 요약·총평·진행 상황 안내를 덧붙이지 마세요. 블록만 출력합니다.
- 도저히 못 풀겠는 문제가 있어도 건너뛰지 말고, 최선의 풀이와 함께 \boxed{}로 답을 내세요.
  (틀린 답은 제가 자동으로 걸러내므로, 억지로 맞히려 하지 말고 정직하게 푸세요)
```

## 2단계 — 묶음 하나씩 처리

1. `data/desktop/problems_001.md` 파일을 대화에 **첨부**하거나 내용을 붙여넣습니다.
2. 메시지는 이 한 줄이면 충분합니다:

   ```
   이 묶음의 모든 문제를 프로젝트 지침의 형식대로 풀어주세요.
   ```

3. 응답이 끝나면 **응답 전체를 복사**해서 `data/desktop/out_001.txt`로 저장합니다.
   (파일명 번호를 문제 묶음 번호와 반드시 맞춰주세요)
4. `data/desktop/INDEX.md`에서 해당 줄에 체크합니다.
5. 다음 묶음은 **새 대화**로 시작하는 편이 좋습니다 — 같은 대화에서 계속하면 앞 문제들이
   문맥에 쌓여 응답이 짧아지거나 형식이 흐트러집니다.

### 응답이 중간에 잘렸을 때
"이어서 계속해주세요"라고 하고, 이어진 응답도 **같은 out_NNN.txt 파일 뒤에 이어 붙이면** 됩니다.
제 파서는 ID 헤더 기준으로 자르기 때문에 파일 안에서 블록이 어디서 끊겼든 상관없습니다.

## 3단계 — 얼마나 할지

전체는 149묶음(2,967문제)입니다. 한 번에 다 하실 필요 없습니다.

**먼저 25묶음(500문제, `problems_001`~`problems_025`)만 해보시길 권합니다.**
그 시점에 제가 채점해서 **교사 정답률**을 뽑습니다. 이 숫자가 이 트랙 전체의 상한을 결정합니다:

- 정답률이 높으면 → 확보 데이터가 많아지므로 전량 진행할 가치가 있습니다
- 정답률이 낮으면 → 우리 모델이 못 푸는 문제는 애초에 매우 어렵다는 뜻이고, 나머지 124묶음을
  진행하기 전에 전략을 다시 짜는 게 맞습니다

부분만 해도 버려지지 않습니다. 있는 만큼으로 학습해서 효과를 측정할 수 있습니다.

## 4단계 — 저에게 넘기기

`data/desktop/out_*.txt`를 저장해두시고 알려주시면 제가 이어받습니다:

```
python api/parse_desktop_output.py --tag desktop     # 채점 + JSONL 변환
python api/build_sft_from_teacher.py --teacher data/teacher_desktop.jsonl
```

이후 서버에서 학습하고, **시드 42/43/44 대응 비교**로 판정합니다
(exp48에서 단일 시드로 봤다면 오판할 뻔했던 전례가 있어, 이번에도 같은 기준을 적용합니다).

## 참고 — 나중에 고려할 선택지

교사도 못 푼 문제가 많이 남으면, 그 문제들만 **정답을 알려주고 다시** 풀이를 받는 방법이 있습니다
(STaR 논문의 rationalization). 수율은 크게 오르지만 "답을 알고 쓴 풀이"가 섞이는 위험이 있어,
1차 결과를 보고 판단하는 게 좋습니다. 필요해지면 그때 별도 묶음 파일을 만들어 드리겠습니다.
