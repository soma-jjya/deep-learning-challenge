# 발표 자료 — 실험 서사와 근거

> 29개 실험(exp01~exp30)의 원본 기록은 `experiments/log.csv`, 서술은 `EXPERIMENTS.md`,
> 시각화는 `report.html`. 이 문서는 그것을 **발표용 이야기**로 재구성한 것이다.
> 평가 배점: 모델 성능 50% + 발표 50% → 이 문서가 후자의 뼈대.

## 한 줄 요약

> **"이미 정밀 조율된 3B 모델에 우리 규모의 추가 학습은 일관되게 해롭다"**를 5번의 학습 실험으로 규명하고,
> 성능은 전부 **추론 시점 설계와 측정의 엄밀함**에서 확보했다. 리더보드 0.648 → **0.78459**.

## 슬라이드 2 — 먼저 만든 것: 신뢰할 수 있는 자

성능 실험 전에 **측정기를 먼저** 세웠다. 이 판단이 이후 모든 결론의 근거가 된다.

| 장치 | 내용 | 효과 |
|---|---|---|
| 고정 검증셋 | train에서 500문제 고정(seed=123), 학습에서 영구 제외 | 실험 간 비교 가능 |
| 오류 문항 제외 | 운영진 공개 627문항 자동 필터 → 유효 483문항 | 라벨 오류로 인한 왜곡 제거 |
| 답 추출기 | `\boxed{}` → 분수·쉼표·LaTeX 기호 → 소수 오추출 방지 | 오답 분석에서 **추출 실패 0건** 달성 |
| 노이즈 기준 | vLLM 연속 배칭 비결정성 실측 → **±1%p 이하는 노이즈로 간주** | 가짜 개선 채택 방지 |

> **초기 사고 사례**: 첫 제출(0.648)은 파일 복사 과정에서 백슬래시가 소실돼 `\boxed` 추출이
> 깨진 채 측정된 점수였다. 이후 모든 정규식을 백슬래시 없이(`chr(92)` 조립) 재작성해
> 복사 경로와 무관하게 동작하도록 고정 — "환경이 코드를 바꾼다"는 교훈.

## 슬라이드 3 — 유일한 대형 이득: Self-Consistency

같은 문제를 여러 번 풀어 다수결. **단일 기법으로는 가장 큰 상승(+5.3%p)**.

| 표본 수 | 정확도 (검증 483문항) |
|---|---|
| greedy (1회) | 69.4% |
| n=4 | 72.7% |
| n=8 | 74.7% |
| n=16 | 75.6% |
| n=32 | 75.4~75.8% |
| n=64 | 75.4~75.6% |

→ **n=16 부근에서 포화**. 표를 4배로 늘려도 같은 다수가 이긴다.

## 슬라이드 4 — 학습 5전 전패, 그리고 그 이유

| 실험 | 방법 | greedy | SC n8 | 판정 |
|---|---|---|---|---|
| 기준 | 베이스 | 69.4% | 74.7% | — |
| exp06 | RFT 자체 풀이 36k, lr 2e-4 | 68.3% | 73.5% | ❌ |
| exp06c | lr 1/4, 1 epoch, 최단 풀이 | 67.9% | 73.3% | ❌ |
| exp09b | 외부 NuminaMath 30k 혼합 | 67.5% | 71.8% | ❌ |
| exp12 | GRPO 파일럿 (400스텝) | 69.2% | 74.5% | ⚪ 중립 |
| exp24 | GRPO 스케일업 (1500스텝) | 69.8% | 73.1% | ❌ |

**진단** — 학습률(4배 범위)·데이터량(13k~43k)·데이터 출처(자체/외부)·학습 패러다임(SFT/RL)을
모두 바꿔도 일관되게 중립 이하. 개별 설정이 아니라 **구조적 원인**:

1. **기존 조율의 파괴** — 베이스는 이미 대규모 SFT+RLHF로 정밀 조율된 모델. 우리 규모의 추가 학습은 얻는 것보다 잃는 것이 크다
2. **다양성 붕괴** — SFT는 출력을 학습 데이터로 수렴시킨다. 그 결과 **SC의 재료(서로 다른 풀이 경로)가 줄어** greedy보다 SC가 더 크게 하락 (exp09b: greedy −1.9%p vs SC −2.9%p) ← 가설의 직접 증거
3. **데이터 편향** — 자기 정답 풀이만 학습하면 이미 푸는 80% 문제만 강화, 못 푸는 20%는 데이터에 존재조차 하지 않는다

> GRPO는 KL 제약 덕분에 **망가뜨리지는 않았다**(성능 보존 확인). 그러나 1,500스텝에서도
> 보상 곡선에 상승 추세가 없어, "덜 돌려서 그렇다"는 가설도 기각됐다.

## 슬라이드 4.5 — 진짜 병목은 "실력"이 아니라 "고르기"였다 (핵심 발견)

같은 문제를 n번 풀었을 때 **정답이 표본 어딘가에 존재하는 비율**(pass@n)을 측정했다.

| 표본 수 | pass@n (정답이 존재) | 우리가 실제로 고른 정답 | 못 고른 몫 |
|---|---|---|---|
| n=8 | 82.0% | 74.7% | 7.3%p |
| n=16 | 84.9% | 75.6% | 9.3%p |
| **n=32** | **87.8%** | 75.8% | **12.0%p** |
| n=64 | 89.9% | 75.4% | 14.5%p |

**모델은 이미 90% 문제의 정답을 만들어낸다.** 우리가 그 답을 고르지 못할 뿐이다.

이 한 장이 프로젝트 전체를 설명한다:
- **학습이 5번 실패한 이유** — 모델의 지식을 늘릴 필요가 없었다. 이미 알고 있었다
- **다수결이 막힌 이유** — 어려운 문제에서 정답은 64표 중 1~2표뿐이라 표결로는 절대 이길 수 없다
- **검증자가 실패한 이유** — 그 소수표를 알아보려면 채점자가 생성자보다 강해야 하는데, 같은 3B 모델로는 불가능하다

## 슬라이드 5 — 선별로 회수할 수 있는가: 검증자 3변형

**관찰**: 6번 샘플링하면 79.9%의 문제에서 정답이 **최소 한 번은 등장**한다. 그런데 다수결로는 74.7%만 건진다.
→ 약 5%p가 "정답이 표본에 있는데 표결에서 밀린" 문제. 이걸 회수하면 목표에 근접.

| 시도 | 방식 | 결과 |
|---|---|---|
| exp10/11 | 확신도(로그확률) 가중 투표 | +0.8%p → −0.4%p (부호 반전, 노이즈) |
| exp18 | 검증자 어댑터 v1 (즉답 Yes/No, 24,000쌍 학습) | 75.4% (+0.5%p, 기준 미달) |
| exp23 | 검증자 v2 (재검산 근거 생성 + 어려운 음성 강조) | 73.7% (v1보다 하락) |
| exp25 | v1 검증자 × n=32 | 75.8% (기준 미달) |

**결론**: 3B 모델은 **자기 풀이를 채점하는 능력이 푸는 능력을 넘지 못한다.** 생성기와 검증자가
같은 한계를 공유하므로, 같은 모델로 만든 검증자는 그 갭을 열지 못한다.

## 슬라이드 6 — 오답의 해부 (exp16)

SC n=8 오답 127건 중 30건을 직접 읽고 분류:

| 유형 | 비율 | 함의 |
|---|---|---|
| 접근 자체 오류 | 67% | 모델 능력의 한계 — 3B의 벽 |
| **정답 라벨 의심** | **23%** | 검증셋 자체의 오염 → 로컬 점수는 실력을 **과소평가** |
| 계산 실수 | 10% | 검증자가 노릴 영역이었으나 회수 실패 |
| **답 추출 실패** | **0%** | 후처리는 이미 완성 — 여기서 얻을 공짜 점수 없음 |

> 이 분석이 로컬 75.8% ↔ 리더보드 0.785의 **+2.7%p 오프셋**을 설명한다.
> (리더보드는 운영진이 정밀 검수한 831문항 = 더 깨끗한 측정기)

## 슬라이드 6.5 — 측정의 한계를 측정하다 (방법론의 정점)

리더보드에 **완전히 동일한 설정으로 두 번 제출**했다. 표본만 다시 뽑았을 뿐인데:

| 제출 | 설정 | 리더보드 |
|---|---|---|
| n32w | 가중 SC n=32 | 0.78459 |
| **w32b** | **똑같은 설정, 표본만 재추출** | **0.77978** |

**같은 방법이 0.48%p 흔들린다.** 이 한 번의 실험이 여러 결론을 바로잡았다:

- 우리 스택의 참값은 0.780±0.005이며, 0.78459는 운이 좋았던 값이다
- 그 전까지 "가중 투표가 +0.7%p 유효하다"고 판단했던 것을 **철회**했다 — 변형들 간 차이(0.777~0.785)가 전부 이 노이즈 안이었다
- 즉 **집계 규칙은 전부 동등**하다는 것이 확정됐고, 이후 39종의 집계 변형 탐색이 모두 76.4%에서 포화한 것과 일치한다

> 대부분의 팀은 리더보드 점수 차이를 실력 차로 읽는다. 우리는 **자기 자신을 대조군으로 제출해** 그 차이의 하한선을 실측했다.

## 슬라이드 7 — 방법론: 노이즈에 속지 않기

같은 설정을 재실행해도 결과가 ±1%p 흔들린다(vLLM 연속 배칭의 비결정성). 이를 실측한 뒤
**모든 실험에 "±1%p 이하는 채택하지 않는다"는 판정 기준을 사전에 명시**했다.

이 원칙 덕분에 기각한 "개선"들 — 프롬프트 앙상블(−0.4%p), 2단계 자기수정(+0.2%p),
문제 텍스트 정화(+4%p이지만 영향 문항 25개 중 1문항), 적응형 예산(−0.4%p).

> 사전에 기준을 정하지 않았다면 이들을 "효과 있음"으로 채택하고 최종 스택을 오염시켰을 것이다.

## 슬라이드 9 — 실험 인프라 (방법론 자산)

3주간 29개 실험을 돌리기 위해 **자율 실험 시스템**을 구축했다.

```
로컬(계획자) ──experiments/queue.md에 실험 정의 → git push──▶ GPU 서버
                                                          ├─ 러너가 큐를 순서대로 실행
                                                          ├─ 서버 Claude가 실행·기록·커밋
                                                          ├─ 결과 → git push → 로컬이 분석
                                                          └─ 유휴 30분 → 자동 정지(과금 차단)
```

- **격리**: 태그 조건부 IAM 정책 + 전용 VPC + 상태 파일 → 기존 클라우드 자원 불가침
- **자가 회복**: 부팅 시 러너 자동 시작, 명령 실패에도 죽지 않는 루프, git 충돌 자동 해소
- **3중 기록**: `log.csv`(정형) + `EXPERIMENTS.md`(서술) + `report.html`(시각화), 실패·중단도 전부 기록
- 총 비용: GPU 약 60~80시간, 100달러 미만

## 슬라이드 9.5 — 소진된 탐색 지도

규칙이 허용하는 범위에서 시도할 수 있는 축을 **전부** 소진했다. 각 항목은 사전에 성공 기준을 정하고 그에 따라 판정했다.

| 축 | 시도 | 최고 결과 | 판정 근거 |
|---|---|---|---|
| 표본 수 | SC n=4~64 | 75.6~75.8% | n=16 이후 포화, LB에서도 n=64 < n=32 |
| 온도 | 0.4 / 0.7 / 1.0 / 혼합 | 75.4% | 0.7이 최적, 혼합도 미달 |
| 샘플링 | top_p 0.8/0.95/1.0 | 미달 | 노이즈 범위 |
| 투표 규칙 | **39종** (가중·trim·길이·폴백·동률처리) | **76.4%** | 7전략 동률 포화 |
| 프롬프트 | 4종 앙상블, few-shot | 74.3% / 73.1% | 다양성 축소로 오히려 손해 |
| 자기수정 | 2단계 검토, Budget Forcing(s1) | 70.0% (greedy 기준) | +0.6%p, 2라운드에서 수렴 |
| 검증자 | v1(즉답), v2(근거생성), ×n32 | 75.8% | 채점 능력 < 생성 능력 |
| 학습 | QLoRA×3 (자체/완만/외부혼합) | 73.5% | 전부 베이스 이하 |
| 학습 | GRPO 파일럿·스케일업 | 74.5% | KL 제약으로 보존만, 보상 곡선 무상승 |

**결론: 이 모델·이 규칙에서 도달 가능한 상한은 로컬 76%대**이며, 그 위는 "고르기" 문제(슬라이드 4.5)가 가로막고 있다.

## 슬라이드 10 — 결론

1. **규칙이 좁힌 탐색 공간에서, 우리는 "무엇이 통하지 않는가"를 체계적으로 규명했다.**
   학습 5전, 검증자 3변형, 추론 잔기술 6종의 실패는 각각 원인이 진단된 실패다.
2. **성능은 추론 설계에서 나왔다.** SC(+5.3%p)와 표본 확대·가중(+1.1%p).
3. **측정을 먼저 세운 것이 가장 큰 투자였다.** 노이즈 기준이 없었다면 잘못된 스택으로 최종전에 갔을 것이다.
