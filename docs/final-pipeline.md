### 선정 근거 (LB 최고점이 아니라 원리로 선택)

- 단순 최고점 기준이면 exp26/exp41b(0.78459)이지만, **exp34b가 "완전히 동일한 설정"을 표본만 다시 뽑아 재실행한 결과 0.77978로 0.48%p 하락**했다 — 즉 0.78459는 참값이 아니라 노이즈 상한에 가까운 관측치. 하나의 관측 최고점을 쫓는 것은 과적합이다.
- 대신 **"가중 SC n=32, temp0.7/top_p0.8, 어댑터 없음"이라는 하나의 설정이 4번 관측**됐다(exp26 0.78459, exp34b 0.77978, exp41b 0.78459[동치], exp38-dt32 0.77978[근사 변형]) — 평균 0.780 근방으로 수렴하며, 이 값이 다른 축(n=64 확대, 가중 제거, 다중시드 병합)보다 항상 같거나 높다. **로컬 검증(75.8%)과도 정합**(오프셋 +2.7%p 일관).
- n=48(0.78219)·n=64(0.77978)·단순다수결(0.77737)·3시드병합(0.77617/0.78459) 등 다른 모든 변형은 n=32 가중 대비 개선이 없거나 노이즈 범위 안에 머물렀다 → **탐색한 축 중 "SC n=32 가중"이 유일하게 반복 검증된 안정적 선택지**.

## ⚠️ 반드시 dump 방식으로 실행할 것

`make_submission.py`를 직접 쓰면 **중단 시 처음부터 재실행**(최대 2.5시간 손실)이다. 리허설에서 확인된 최대 리스크.
아래 2단계 방식은 100문항마다 저장돼 **어디서 죽어도 이어서 재개**된다.

### 1단계 — 표본 생성 (약 2시간 30분, 재개 가능)

```bash
cd ~/work/deep-learning-challenge && git pull
nohup uv run python remote/dump_lb_samples.py \
  --n 32 --temp 0.7 --top-p 0.8 --seed 42 \
  --lb-csv deep-learning-challenge-2026/<최종test파일>.csv \
  --out results/final_samples.jsonl > dump_final.log 2>&1 &
```

- 진행 확인: `tail -f dump_final.log` → "진행 N/<전체>문항"
- **중단됐다면 같은 명령을 그대로 재실행** (완료분은 건너뜀). 재실행 전 `.progress`의 done 개수와 jsonl 줄 수 일치 확인

### 2단계 — 제출 파일 생성 (수 초, GPU 불필요)

```bash
uv run python remote/make_submission_from_dump.py \
  --dump results/final_samples.jsonl --rule weighted --n 32 \
  --lb-csv deep-learning-challenge-2026/<최종test파일>.csv --tag final
```

### 3단계 — 제출 전 검증 (필수)

- 행수 = **test 파일의 실제 문항 수** / 컬럼 `id`,`answer` / answer 전부 정수 / 결측·중복 0건
- **`id`는 소문자** (대회 문서엔 `ID`로 적혀 있으나 채점기는 소문자 — 2026-07-31 첫 제출 ERROR로 확인된 사항)

### 4단계 — 제출

```bash
python -m kaggle competitions submit -c deep-learning-challenge-2026 \
  -f results/submission_final.csv -m "final | weighted SC n32 | local 75.8%"
```

**⚠️ 최종 제출은 사용자 확인 후에만. 자동 제출 금지.**

> test가 3,000문항을 넘을 수도 있다. **아래 표의 2,000은 가정이며, 당일 실제 행 수로 다시 계산할 것.**

**당일 첫 번째로 할 일** — 파일을 열자마자 문항 수를 세고 소요를 계산한다:

```bash
python -c "import csv; print('문항 수:', sum(1 for _ in csv.DictReader(open('deep-learning-challenge-2026/<최종test파일>.csv',encoding='utf-8'))))"
```

| test 문항 수 | n=32 생성 시간 | n=16 생성 시간 |
|---|---|---|
| 2,000 | 2시간 28분 | 1시간 14분 |
| 2,500 | 3시간 05분 | 1시간 33분 |
| 3,000 | 3시간 42분 | 1시간 51분 |
| 3,500 | 4시간 19분 | 2시간 10분 |

계산식: `시간 = 문항수 × 4.44초 ÷ 3600` (n=32 실측치, exp30 리허설 831문항 기준)

**시간이 빠듯하면 주저 말고 `--n 16`으로 내릴 것.** 로컬 검증에서 n=16은 75.6%, n=32는 75.8%로
차이가 0.2%p이며 이는 측정 노이즈(±1%p) 한참 안쪽이다 — **생성 시간을 절반으로 줄이는 대가로
잃는 것이 사실상 없다.** 제출 자체를 못 하는 것이 유일한 실패이므로 이 교환은 언제나 유리하다.

| 구간 | 소요 | 비고 |
|---|---|---|
| 표본 생성 | 위 표 참조 | 4.44초/문항 (n=32) |
| 집계·검증 | 5분 | GPU 불필요 |
| **중단 1회 대비 여유** | 생성 시간만큼 | 재개되므로 실제로는 부분 손실만 |
| **권장 착수 시각** | **마감 (생성시간 × 2 + 1시간) 전** | 2,000문항이면 6시간, 3,500문항이면 9시간 30분 |
